## Decisions Made

**Decision (#decision #action):** Use Polaris Alpha as primary OpenRouter model
- **Rationale:** User-specified model currently available on OpenRouter; previous alpha models (horizon-beta, cypher-alpha) returned 404 errors.
- **Alternatives considered:** GPT-4o, Claude 3.5 Sonnet, GPT-4 Turbo, Llama 3.1 70B (kept as fallback clients)
- **Anchors:** baml_src/clients.baml:7-16, test execution showing successful response from openrouter/polaris-alpha
- **Impact:** All three pipelines now use PolarisAlpha client; fallback strategy available if needed

**Decision (#decision):** Rename BAML functions to avoid class name conflicts
- **Rationale:** BAML requires unique names across functions and classes; initial naming (ProbeNarrative → NarrativeProbe) caused compilation errors
- **Alternatives considered:** Rename classes instead (rejected—class names align with MAVEN/CHROMA terminology)
- **Implementation:** Functions renamed to verb phrases: AnalyzeNarrative, GenerateCounterRitual, PerformSerologicScan
- **Anchors:** baml_src/pipelines.baml:5,57,110, BAML generation error output
- **Impact:** CLI accepts both CamelCase and snake_case aliases for convenience

**Decision (#decision):** Add explicit output format instructions to prompts
- **Rationale:** Initial model responses wrapped JSON in extra structure (`{ "SerologicScan": {...} }`); BAML parser expected flat structure
- **Implementation:** Added "Respond with ONLY the JSON object matching the schema above. Do not wrap it in any additional structure." to all pipeline prompts
- **Anchors:** baml_src/pipelines.baml:52,105,169
- **Impact:** Model now returns correctly formatted JSON; parsing succeeds consistently

- [#pattern] ESM module system (`"type": "module"`) works seamlessly with BAML generated client, tsx, and dotenv (anchors: package.json:5, src/index.ts:6-7, successful test execution)
- [#pattern] Extracting working API keys from existing projects (basilisk) accelerates development—no manual signup required (anchors: basilisk/baml_src/clients.baml:191, kit2/modules/baml-openrouter/.env)

- [#failure] First prompt attempt resulted in wrapped JSON output incompatible with BAML parser; needed explicit "do not wrap" instruction (anchors: test error showing nested SerologicScan object, fixed prompt in pipelines.baml:169)

**Patterns noticed:**
- [#pattern] MAVEN serologic scan produces remarkably coherent analysis even on simple inputs; Polaris Alpha identified "scarcity" macro, 0.78 viral load, and "transparency injection" weak link for "Limited time! Only 3 spots left!" (anchors: test output JSON, viral_load score, beneficiaries list)
